# Orbit AI — independent deep audit report

**Target:** `Orbit-AI-Final.zip` as found in the uploaded workspace, audited from its actual ZIP contents rather than relying on the earlier completion report.  
**Audited source:** Python/FastAPI backend, RAG orchestration and helpers, provider adapters, SQLite/Supabase repositories, SQL migrations, React/Vite dashboard source and retained static assets, widget, backup/restore tooling, environment template, Docker configuration, tests and docs.  
**Result:** Corrected locally verifiable defects and produced `Orbit-AI-Final-Audited.zip`. This is not a claim that the application is bug-free or production-ready; external service and build gates remain blocked as listed below.

## Executive assessment

The initial archive's core Python regression tests passed, but the independent code audit found multiple correctness, resilience, security-hardening, and release hygiene defects. Fixes were made in the audited working copy and protected with regression tests. The final local suite passes **55 tests**, compilation succeeds, and the final archive is validated after clean extraction. The 24-test Advanced RAG reference suite also passes independently, but neither result proves external providers work.

The release acceptance status is **conditionally verified**. The main remaining blockers are the missing live Supabase/Postgres, Qdrant, LLM/embedding and SMTP services/credentials; unavailable npm package cache/network for dashboard rebuild/browser E2E; and the absence of the Docker and PostgreSQL command-line tools in this environment.

## Findings and fixes

Severity represents the impact of the confirmed behavior in the audited source, not a claim that the same issue is exploitable in every deployment.

| ID | Severity | Confirmed issue in audited source | Fix made and verification |
|---|---|---|---|
| A-01 | High | Retrieved tenant documents were placed in the LLM instruction/system channel, increasing the chance that a hostile uploaded document could override task instructions. | Moved retrieved evidence into an explicitly delimited user message as `UNTRUSTED_TENANT_KNOWLEDGE`; system instructions explicitly describe documents/history as untrusted data. Regression test asserts hostile document text is absent from the system role and present only in the reference-data block. **PASS** (mocked adapter payload test; no claim of formal prompt-injection immunity). |
| A-02 | High | Tenant deletion removed the metadata record before remote storage/vector cleanup completed. A remote cleanup failure could orphan data without a retryable tenant record. | Disable tenant first; perform cleanup; delete metadata only after provider cleanup succeeds. On cleanup error, return `503 TENANT_CLEANUP_INCOMPLETE` and keep the tenant disabled for a safe retry. API regression verifies failure then successful retry. **PASS** locally with a fault-injected provider. |
| A-03 | High | Backup restore validation rejected traversal, but allowed malformed ZIP path/type collisions such as a file where `objects/` should be a directory or file/directory ancestors in the same archive. | Validate allowed roots, file-vs-directory types, duplicate normalized names, descendants under files, symlinks/special files, path separators, encryption and expansion limits before extraction. New tests cover root-type and ancestor conflicts. **PASS**. |
| A-04 | High | Request body limiting depended on `Content-Length`, which can be absent on chunked requests. | Enforce byte limits while receiving the body. Regression exercises an oversized request without `Content-Length` and expects 413. **PASS**. |
| A-05 | Medium–High | The configured default file outbox called a missing `now()` helper, so lead notification queueing could fail. | Add UTC timestamp helper shared by provider adapters. Test default outbox path and timestamp payload. **PASS** locally; outbox queues records and does not deliver email by itself. |
| A-06 | Medium–High | A knowledge rebuild could replace/clear a tenant vector index before successful embedding of all replacement text. | Build/validate replacement vectors before invoking tenant replacement. Added fault-injection regression that proves an embedding failure leaves old indexed content intact and metadata unchanged. **PASS**. |
| A-07 | Medium–High | Embedding dimensions could diverge from Supabase's fixed `vector(128)` schema; OpenAI `text-embedding-3-*` request was not consistently told to return the configured width. | Add `OPENAI_EMBEDDING_DIMENSIONS`, send `dimensions` to supported embedding models, validate response vectors, default dimensions to Supabase schema dimensions when applicable, and reject mismatch at configuration. **PASS** with configuration and fake HTTP adapter tests; live model unverified. |
| A-08 | Medium | Filename sanitization was not consistent through upload, metadata, index, and deletion paths. | Use one canonical sanitized filename across persisted blob, source identifier, metadata, listing and delete. | A-10 | Medium | CSV export could emit attacker-controlled cell values beginning with spreadsheet formula markers. | Neutralize formula-leading `=`, `+`, `-`, and `@` after leading whitespace before CSV serialization. Regression covers formula payloads. **PASS**. |

## Remaining risks and limits

1. **No live provider proof.** Tests with fake HTTP responses prove adapter behavior under tested cases, not actual Supabase, Qdrant, LLM/embedding or SMTP connectivity.
2. **Migration 0003 is not applied.** Apply migrations in order only after a separate backup and staging rehearsal. Until then, the domain allowlist fallback uses compensating REST requests, not an actual transaction.
3. **Cross-service updates are not a single transaction.** A blob, vector index, and metadata repository can fail independently. Upload/delete compensation is best effort and cannot guarantee consistency after multiple simultaneous failures or an unreachable provider. Reconcile/monitor failed updates operationally.
4. **Retrieval scale cap.** Hybrid lexical/BM25 reranking uses up to the first 2,000 tenant chunks exposed by `list_tenant`; larger tenants can be biased/truncated for lexical reranking even where the dense provider indexes more data. A paginated/candidate-first corpus architecture is recommended before large-scale rollout.
5. **Heuristic query understanding.** Hindi/Hinglish detection and query rewriting use offline heuristics (`provider="none"`); no semantic rewrite model or translated query guarantee is asserted.
6. **Grounding is heuristic, not formal entailment.** Numeric and topic-conflict checks catch selected classes of error; they do not prove every generated claim is entailed by sources. Citation output refers to retrieved source chunks, not formal claim-to-citation validation.
7. **SSE is buffered.** `/v1/chat/stream` returns SSE events for the fully generated, checked response; `LLM_STREAM` is parsed but does not cause live upstream token streaming.
8. **Outbox delivery requires a consumer.** The default local `outbox` only writes notification JSON. A configured `smtp` provider attempts mail directly; Supabase outbox inserts a pending row. Confirm an operational delivery worker exists before promising delivery.
9. **Rate limiting is process-local.** Multiple replicas need gateway/proxy-level throttling.
10. **Authenticated provider-test SSRF.** `/admin/settings/provider/test` calls an operator-supplied URL. It is admin-key protected, but deployments should restrict outbound network access so a compromised admin credential cannot probe internal control-plane addresses.
11. **Frontend release is not rebuilt.** Existing compiled assets are shipped, but no successful reproducible npm install/build or Playwright/browser E2E could run in this network-restricted environment.
12. **Dependency environment warning.** `pip check` fails on shared environment package pair MoviePy/Pillow, but both are outside Orbit's declared runtime dependency list. This environment still requires clean isolated dependency validation before a production image is accepted.
13. **Persistence compatibility.** The shipped SQLite database was excluded; the audited copy was empty. No production customer database was migrated or packaged. Existing production data requires a reviewed backup and staging migration/rollback test.

## Acceptance decision

**Conditionally verified for local development and further staging validation. Not declared bug-free or fully production accepted.** The evidence proves the local regression suite, package compilation/build/install checks, and final ZIP checks listed in the verification ledger only. All external/deployment gates remain exactly as marked there.
